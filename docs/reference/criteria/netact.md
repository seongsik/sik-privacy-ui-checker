# 정보통신망 이용촉진 및 정보보호 등에 관한 법률·시행령·시행규칙 (3단 비교)

- 원문: `scratchpad\src\netact.txt` 1~2712줄 전체(국가법령정보센터 3단 비교)
  - 법률 제21988호(2026. 9. 29. 일부개정), 시행령 대통령령 제36728호(2026. 9. 29. 타법개정), 시행규칙 과학기술정보통신부령 제71호(2021. 3. 31.)
- 범위: 웹서비스 운영자(정보통신서비스 제공자)의 개인정보·이용자 보호·보안 관련 의무만 항목화. 제외한 장·조는 끝의 추출 메모에 적음.
- 표기: "법"은 정보통신망법, "영"은 같은 법 시행령, "규칙"은 시행규칙. 원문 파일에 쪽 번호가 없어 원문 줄 번호(L)를 함께 적음.

## A. 단말기 접근권한·주민등록번호·연계정보·본인확인

### NET-22B-01 앱 접근권한 고지·동의(필수/선택 구분)
- 근거: 법 제22조의2제1항(L225-232), 제5항; 영 제9조의2제1항·제2항(L239-247); 과태료 법 제76조제2항제1호·제1호의2
- 요구사항: 앱이 단말기 저장정보(연락처·일정·사진·통신내용·바이오정보), 자동 저장정보(위치·통신기록·인증정보·신체활동), 단말 고유식별정보(IMEI 등), 입력·출력 기능(카메라·마이크·센서)에 접근하려면 필수 권한은 항목·이유를, 선택 권한은 항목·이유·동의하지 않아도 된다는 사실을 명확히 알리고 동의를 받아야 한다. 개별 선택 가능한 OS에서는 필수/선택을 구분해 알린 뒤 최초 접근 시 동의를 받는다(OS가 개별 선택 불가면 필수 권한만 설정해 설치 시 동의).
- 적용조건: 이동통신단말장치용 앱(하이브리드 앱·웹뷰 앱 포함)을 제공하는 정보통신서비스 제공자. 순수 웹사이트는 직접 대상 아님(브라우저 권한 요청은 비고 참고)
- 점검유형: 관찰
- 점검위치: 앱 설치·최초 실행 안내 화면, 앱 소개 페이지(웹), 처리방침 페이지, 모바일 웹에서 권한 요청 시점
- 점검방법: (1) 웹사이트에 앱 다운로드·소개 페이지가 있으면 접근권한 안내(필수/선택 구분, 항목, 이유, 선택 거부 가능 문구)를 페이지 텍스트로 확인. (2) 처리방침에서 접근권한 안내 조항 확인. (3) 모바일 웹은 페이지 로드 직후 위치·카메라·마이크·알림 권한 요청이 뜨는지 관찰하고, 읽기 전용 JS로 `navigator.permissions.query({name:'geolocation'})` 등 상태만 조회(권한 허용·거부는 누르지 않음). (4) 앱 자체 화면은 브라우저로 볼 수 없으므로 사용자에게 설치 화면·최초 실행 권한 팝업 스크린샷을 요청.
- 양호기준: 필수·선택 권한이 구분 표시되고, 권한별 항목과 이유가 있으며, 선택 권한에 "동의하지 않아도 서비스 이용 가능" 취지가 있음. 권한 요청이 해당 기능 최초 사용 시점에 이루어짐.
- 취약기준: 권한 안내 없음, 필수/선택 미구분, 이유 누락, 선택 권한을 필수처럼 표시, 기능과 무관한 권한(예: 쇼핑앱의 연락처·통화기록) 요청, 앱 실행 즉시 모든 권한 일괄 요청.
- 조치방안: 앱 최초 실행 시 별도 안내 화면을 두고 "[필수] 저장공간: 사진 첨부 / [선택] 위치: 주변 매장 찾기(허용하지 않아도 서비스 이용 가능)"처럼 권한별 항목·이유·선택 여부를 표로 표시한다. Android 6.0 이상·iOS는 런타임 권한으로 구현하고 해당 기능 진입 시점에 요청한다. 처리방침에 "앱 접근권한" 조항을 두고 동일 내용과 철회 방법(OS 설정 > 앱 > 권한)을 적는다. 신규 권한 추가 시 개발·배포 체크리스트에 권한 필요성 검토를 넣는다.
- 증적: 앱 소개·처리방침의 권한 안내 부분 스크린샷, 사용자 제공 앱 권한 팝업 스크린샷, permissions.query 결과
- 비고: 법령 의무(과태료는 제2항 위반=서비스 거부 시, 제3항 조치 미이행 시). 웹 브라우저의 위치·카메라 권한 요청은 엄밀히 이 조 대상은 아니나, 같은 기준(사용 시점 요청, 이유 안내)을 권고로 적용 가능. 판단 시 영 제9조의2제3항에 따라 약관·처리방침에 공개된 서비스 범위와 이용자의 합리적 예상, 기술적 관련성을 고려한다. PIPA-22과 관계(선택 동의 거부 시 서비스 거부 금지 원칙).

### NET-22B-02 선택 접근권한 미동의를 이유로 한 서비스 거부 금지
- 근거: 법 제22조의2제2항(L233); 과태료 법 제76조제2항제1호(L2587)
- 요구사항: 서비스 제공에 반드시 필요하지 않은 접근권한에 동의하지 않았다는 이유로 서비스 제공을 거부해서는 안 된다.
- 적용조건: 앱(모바일 웹 포함)을 제공하는 정보통신서비스 제공자
- 점검유형: 능동(승인)
- 점검위치: 앱 최초 실행·권한 팝업, 모바일 웹 권한 요청 화면
- 점검방법: 사용자 승인 후, 사용자가 테스트 단말·테스트 계정으로 선택 권한(위치·연락처·알림 등)을 "거부"로 선택하고 Claude는 이후 앱/웹이 종료되거나 진입을 막는지, 핵심 기능(로그인·조회·결제 등)이 계속 동작하는지 관찰·기록한다. 모바일 웹은 브라우저 권한 팝업에서 사용자가 거부한 뒤 동작을 관찰.
- 양호기준: 선택 권한 거부 후에도 해당 권한과 무관한 기능이 정상 동작하며, 권한이 필요한 기능에서만 재요청 안내가 뜸.
- 취약기준: 선택 권한 거부 시 앱 종료·무한 재요청·진입 차단, 또는 "모든 권한을 허용해야 이용 가능" 문구.
- 조치방안: 권한별 의존 기능을 분리해, 거부 시 해당 기능만 비활성화하고 "위치 권한을 허용하면 주변 매장을 볼 수 있습니다 [설정으로 이동]" 같은 안내를 띄운다. 앱 실행 시 일괄 권한 요청 코드를 제거한다. QA 시나리오에 "선택 권한 전부 거부" 케이스를 넣는다.
- 증적: 거부 선택 후 화면 스크린샷(사용자 화면), 오류·차단 메시지
- 비고: 법령 의무. 단말 권한 설정 변경은 서비스 데이터 수정은 아니지만 사용자 단말 조작이므로 사용자가 직접 수행. PIPA-22과 관계.

### NET-22B-03 접근권한 동의 철회 방법 구현
- 근거: 법 제22조의2제3항(L234); 영 제9조의2제4항제3호(L249-252); 과태료 법 제76조제2항제1호의2(L2588)
- 요구사항: 단말기 소프트웨어 제작·공급자는 OS·단말기에 맞는 접근권한 동의 및 철회 방법을 소프트웨어에 구현해야 한다.
- 적용조건: 앱을 직접 제작·공급하는 자(외주 개발 시 공급 주체)
- 점검유형: 관찰
- 점검위치: 처리방침 접근권한 조항, 앱 설정 화면(사용자 제공 스크린샷), 고객센터 FAQ
- 점검방법: 처리방침·FAQ에 권한 철회 방법(OS 설정 경로 또는 앱 내 설정 메뉴)이 안내되는지 확인. 앱 내부 설정 메뉴는 사용자 제공 스크린샷으로 확인.
- 양호기준: 철회 방법이 안내되고 실제 OS 설정 또는 앱 내 메뉴로 철회 가능.
- 취약기준: 철회 방법 안내 없음, 구버전 OS(개별 선택 불가)를 대상으로 하면서 대체 철회 수단 없음.
- 조치방안: 처리방침·FAQ에 "Android: 설정 > 애플리케이션 > [앱명] > 권한, iOS: 설정 > [앱명]"처럼 철회 경로를 적고, 가능하면 앱 내 [설정 > 권한 관리]에서 OS 설정으로 바로 이동하는 버튼을 둔다. targetSdkVersion을 런타임 권한 지원 버전 이상으로 유지한다.
- 증적: 처리방침 해당 조항 스크린샷, 앱 설정 화면(사용자 제공)
- 비고: 법령 의무. OS 제작자·단말 제조자 의무(영 제9조의2제4항제1호·제2호)는 웹서비스 운영자와 무관해 제외.

### NET-23B-01 주민등록번호 수집·이용 금지
- 근거: 법 제23조의2제1항·제2항(L260-264); 과태료 법 제76조제2항제2호(L2589)
- 요구사항: 정보통신서비스 제공자는 본인확인기관으로 지정받은 경우 등 예외를 제외하고 이용자의 주민등록번호를 수집·이용할 수 없다. 예외(이동통신 재판매사업자)로 수집할 수 있는 경우에도 주민등록번호를 쓰지 않는 본인확인 대체수단을 제공해야 한다.
- 적용조건: 모든 정보통신서비스 제공자(본인확인기관, 재판매 이통사 예외). 다른 법령 근거가 있으면 PIPA 제24조의2 기준으로 판단
- 점검유형: 관찰
- 점검위치: 회원가입, 본인확인, 아이디·비밀번호 찾기, 주문·결제, 이벤트 응모, 고객문의, 마이페이지(회원정보 수정)
- 점검방법: (1) 각 화면의 입력 필드 라벨·placeholder·name 속성을 DOM으로 조회해 "주민", "jumin", "rrn", "ssn", "resident" 등이 있는지 확인(값 입력·제출은 하지 않음). (2) 생년월일+성별 뒷자리 1자리 외에 13자리 입력란이 있는지 확인. (3) 마이페이지·주문내역 응답 본문(네트워크 탭)에 13자리 주민등록번호 패턴(\d{6}-?[1-8]\d{6})이 있는지 검색. (4) 외부 본인확인(휴대폰·아이핀·PASS 등) 연동이면 사업자 페이지가 아닌 본인확인기관 도메인에서 입력받는지 확인.
- 양호기준: 사업자 화면·요청·응답 어디에도 주민등록번호 전체 또는 뒷자리 입력·전송·노출이 없고, 본인확인은 본인확인기관 서비스로 위탁.
- 취약기준: 사업자 화면에 주민등록번호 입력란 존재, 네트워크 요청·응답에 주민등록번호 포함, 처리방침 수집항목에 주민등록번호 기재(법령 근거 없음).
- 조치방안: 주민등록번호 입력란을 제거하고 본인확인은 본인확인기관(휴대폰 본인확인, 아이핀, 금융인증서 등) 연동으로 바꾼다. 필요 시 생년월일·성별만 받는다. 기존 보유분은 파기 계획을 세워 파기하고 처리방침 수집항목을 고친다. 법령 근거로 처리하는 경우 근거 조문을 처리방침에 적고 암호화 보관한다.
- 증적: 입력 필드 DOM 속성(스크린샷 또는 속성 목록), 해당 네트워크 요청 URL·필드명(값은 마스킹 필요), 처리방침 수집항목
- 비고: 법령 의무. 정보통신서비스 제공자에게는 PIPA 제24조의2보다 엄격한 특칙으로 읽히나, 2020년 개정 후 PIPA와 함께 적용되므로 판단은 PIPA 항목과 함께. PIPA-24B과 관계.

### NET-23E-01 연계정보(CI) 목적 범위 내 처리
- 근거: 법 제23조의5제4항(L360)
- 요구사항: 본인확인기관에서 연계정보를 제공받은 연계정보 이용기관은 제공받은 목적 범위에서만 연계정보를 처리할 수 있고, 다른 목적은 정보주체의 별도 동의를 받은 범위에서만 처리할 수 있다.
- 적용조건: 본인확인서비스(휴대폰·아이핀 등)를 통해 CI를 받는 사업자(연계정보 이용기관)
- 점검유형: 관찰
- 점검위치: 본인확인 완료 후 콜백·회원가입 완료 화면, 마이페이지, 처리방침
- 점검방법: (1) 본인확인 결과 콜백 및 이후 API 응답 본문에서 CI(88자 Base64 형태, 필드명 ci, conn_info 등)가 브라우저로 내려오는지 확인(사용자 본인 계정에 한함). (2) 처리방침에 CI 수집 목적·이용 범위가 적혀 있는지 확인. (3) CI를 마케팅·제3자 제공 등에 쓴다는 기재가 있으면 별도 동의 화면이 있는지 확인.
- 양호기준: CI가 클라이언트에 노출되지 않거나 노출이 불가피한 경우 서버 처리 직후 폐기, 처리방침에 목적 범위 명시, 목적 외 처리 시 별도 동의.
- 취약기준: CI가 화면·로컬스토리지·쿠키·불필요한 API 응답에 남음, 목적 외 이용(예: 타 서비스 회원 매칭)을 별도 동의 없이 수행.
- 조치방안: CI는 서버 간 통신(본인확인기관→사업자 서버)으로만 받고 브라우저 응답·쿠키·localStorage에 남기지 않는다. 처리방침 수집항목에 "연계정보(CI): 중복가입 확인·본인 식별"처럼 목적을 적는다. 목적 외 이용 시 "연계정보를 ○○ 목적으로 이용하는 데 동의합니다(선택)" 별도 동의를 받는다.
- 증적: 해당 API 응답의 필드명(값 마스킹 필요), localStorage·cookie 키 목록, 처리방침 해당 부분
- 비고: 법령 의무. CI 값은 개인정보이므로 증적에서 반드시 마스킹. PIPA-15·PIPA-18과 관계.

### NET-23F-01 연계정보 안전조치(이용기관)
- 근거: 법 제23조의6제2항·제3항(L415-416); 영 제13조제2항(L428-435), 제14조제2호(L440); 과태료 법 제76조제2항제2호의6(L2594)
- 요구사항: 연계정보 이용기관은 PIPA 제29조 안전조치 외에 (1) 안전조치 총괄 책임자 지정·내부규정 수립, (2) 제공 목적 범위 내 처리, (3) 주민등록번호를 보관하는 경우 CI와 분리 보관, (4) CI 저장·전송 암호화, (5) CI 분실·도난 등 침해사고 대응계획, (6) CI 제공기관·제공시기 기록·보관, (7) 고시 사항을 이행해야 한다.
- 적용조건: 연계정보 이용기관. 실태점검 대상은 CI를 1,000건 이상 제공받은 자(영 제14조제2호)
- 점검유형: 서면
- 점검위치: 본인확인 연동 화면(전송 구간), 서면
- 점검방법: 서면 확인: CI 관리 내부규정·책임자 지정 문서, DB 스키마(CI 컬럼 암호화 여부, 주민등록번호와 분리 여부), CI 수신 이력 기록(제공기관·일시), 침해사고 대응계획. 브라우저 보조 확인: 본인확인 연동 구간이 HTTPS인지, CI가 브라우저 응답에 평문으로 노출되는지(NET-23E-01과 함께).
- 양호기준: 7개 조치가 문서·시스템으로 확인되고 CI가 암호화 저장·전송됨.
- 취약기준: 책임자·규정 없음, CI 평문 저장, 주민등록번호와 동일 테이블 보관, 수신 이력 미기록.
- 조치방안: 개인정보 내부관리계획에 "연계정보 안전조치" 장을 추가해 책임자(통상 CPO)를 지정하고, CI 컬럼을 양방향 암호화(AES-256 등)로 저장하며 전송은 TLS 1.2 이상으로 한다. CI 수신 로그(제공 본인확인기관명, 수신 일시, 목적)를 남기고 보관기간을 정한다. 침해사고 대응 매뉴얼에 CI 유출 시나리오를 넣는다.
- 증적: 서면 문서 목록, 본인확인 연동 요청의 프로토콜·도메인
- 비고: 법령 의무(2024.1.23. 신설, 시행령 2025.5.20. 신설). 세부는 방송미디어통신위원회 고시 위임(원문 미제공). PIPA-29과 관계, SAFE 항목과 관계.

### NET-44E-01 공공기관등 게시판 이용자 본인확인
- 근거: 법 제44조의5제1항·제4항(L712-717)
- 요구사항: 국가기관·지방자치단체·공기업·준정부기관·지방공사·지방공단이 게시판을 설치·운영하려면 게시판 이용자의 본인확인 방법·절차 등 본인확인조치를 해야 한다.
- 적용조건: 공공기관등(법 제44조의5제1항제1호). 민간 사업자 의무 조항은 위헌결정으로 삭제(2014)
- 점검유형: 관찰
- 점검위치: 게시판 글쓰기 화면, 게시판 이용 안내
- 점검방법: 게시판 글쓰기 버튼을 눌러 진입 단계에서 로그인 또는 본인확인(휴대폰·아이핀·간편인증 등)을 요구하는지 관찰한다. 글 작성·등록은 하지 않는다.
- 양호기준: 글쓰기 진입 전 본인확인 또는 본인확인된 회원 로그인을 요구하고, 본인확인 시 주민등록번호를 직접 받지 않음.
- 취약기준: 공공기관 게시판에 본인확인 없이 익명 작성 가능, 또는 본인확인 수단으로 주민등록번호를 직접 입력받음.
- 조치방안: 게시판 글쓰기에 본인확인기관 연동(휴대폰·아이핀·간편인증) 또는 본인확인 완료 회원 로그인을 적용하고, 본인확인 정보는 작성자 식별에 필요한 최소 정보만 보관한다. 게시판 운영 지침에 본인확인 절차를 적는다.
- 증적: 글쓰기 진입 시 본인확인 요구 화면 스크린샷
- 비고: 법령 의무(공공기관등 한정). 본인확인 결과 보관은 PIPA-21과 관계, 주민등록번호 미수집은 NET-23B-01과 관계.

### NET-32E-01 국내대리인 지정·공개(국외 사업자)
- 근거: 법 제32조의5제1항~제3항(L535-542); 영 제19조(L546-551); 과태료 법 제76조제3항제4호의3(L2623)
- 요구사항: 국내에 주소·영업소가 없는 정보통신서비스 제공자 중 전년도 매출액 1조원 이상, 정보통신서비스 부문 매출액 100억원 이상, 또는 자료제출을 요구받은 자는 국내대리인을 서면으로 지정하고, 국내대리인의 성명(법인은 명칭·대표자), 주소(영업소 소재지)·전화번호·전자우편 주소를 인터넷 사이트 등에 공개해야 한다.
- 적용조건: 국외 정보통신서비스 제공자로서 영 제19조 기준 해당자
- 점검유형: 관찰
- 점검위치: 처리방침 페이지, 사이트 하단(푸터), 회사 소개·법적 고지 페이지
- 점검방법: 처리방침·푸터·법적 고지 페이지 텍스트에서 "국내대리인" 항목과 성명·주소·전화번호·이메일 4개 요소가 모두 있는지 확인한다.
- 양호기준: 국내대리인 항목이 있고 4개 요소가 모두 공개됨.
- 취약기준: 적용 대상인데 국내대리인 공개가 없거나 요소 일부 누락.
- 조치방안: 처리방침에 "국내대리인: ○○주식회사(대표 ○○○), 주소 ○○, 전화 ○○, 이메일 ○○" 조항을 추가하고 사이트 하단에도 링크를 둔다. 국내대리인 지정 계약서(서면)를 갖춘다.
- 증적: 공개 위치 스크린샷
- 비고: 법령 의무. 망법상 국내대리인 대리 범위는 2020년 이후 제64조 자료제출만 남았고, 개인정보 관련 국내대리인은 PIPA 제31조의2가 별도로 규정. PIPA-31B과 관계(처리방침 기재는 STD-19-01과도 관계).

## B. 청소년 보호·게시물 권리침해 대응

### NET-42-01 청소년유해매체물 표시
- 근거: 법 제42조(L615); 영 제24조(L617-619); 법 제44조의2제3항(L663)
- 요구사항: 청소년유해매체물을 제공하는 자는 19세 미만은 이용할 수 없다는 취지를 누구나 쉽게 확인할 수 있게 음성·문자·영상으로 표시하고, 인터넷 제공자는 기호·부호·문자·숫자로 된 전자적 표시도 함께 해야 한다(구체 방법은 방송미디어통신위원회 고시). 표시방법을 지키지 않은 청소년유해매체물이 게재되어 있으면 정보통신서비스 제공자는 지체 없이 삭제해야 한다.
- 적용조건: 청소년유해매체물(성인 콘텐츠, 주류·담배 판매 등 청소년유해 결정 매체물)을 제공하거나 게재된 정보통신망을 운영하는 자
- 점검유형: 관찰
- 점검위치: 성인 콘텐츠 메뉴·상품 상세, 성인인증 화면, 해당 페이지의 HTML head
- 점검방법: (1) 유해매체물 페이지 진입 전·진입 시 "19세 미만 이용 불가" 문구·19 표시 이미지가 보이는지 화면으로 확인. (2) 페이지 소스(DOM)의 meta 태그·헤더에서 고시에 따른 전자적 표시(청소년유해 라벨)가 있는지 조회. (3) 성인인증 전 상태(로그아웃)에서 해당 콘텐츠 본문이 노출되는지 확인.
- 양호기준: 화면 표시(문구·19 마크)와 전자적 표시가 모두 있고, 성인인증 전에는 본문이 노출되지 않음.
- 취약기준: 표시 없음, 화면 표시만 있고 전자적 표시 없음, 표시 없는 유해매체물 게시물이 방치됨.
- 조치방안: 성인 콘텐츠 페이지 상단에 "이 정보 내용은 청소년유해매체물로서 「청소년 보호법」 및 「정보통신망법」에 따라 19세 미만의 청소년이 이용할 수 없습니다" 문구와 19 마크를 표시하고, 고시가 정한 전자적 표시를 HTML head에 넣는다. 게시판 이용자가 올린 미표시 유해물은 모니터링해 삭제하는 운영 절차를 둔다.
- 증적: 표시 화면 스크린샷, meta 태그 목록
- 비고: 법령 의무. 전자적 표시의 구체 형식은 방송미디어통신위원회 고시 위임(원문 미제공) — 형식 판정은 고시 확인 필요. 성인인증은 NET-42B-01과 관계.

### NET-42B-01 청소년유해매체물 광고의 청소년 접근제한
- 근거: 법 제42조의2(L622); 법 제44조의2제3항(L663)
- 요구사항: 청소년유해매체물을 광고하는 정보를 청소년에게 전송하거나 청소년 접근을 제한하는 조치 없이 공개적으로 전시해서는 안 되며, 운영자는 그런 광고가 전시되어 있으면 지체 없이 삭제해야 한다.
- 적용조건: 성인용 상품·콘텐츠 광고·배너를 게재하는 사이트, 이용자 게시판을 운영하는 자
- 점검유형: 관찰
- 점검위치: 메인·목록 화면의 배너·광고 영역, 검색 결과, 성인 상품 목록
- 점검방법: 로그아웃 또는 미인증 상태로 메인·목록·검색 화면을 탐색해 성인용 상품 이미지·광고가 성인인증 없이 노출되는지 관찰한다.
- 양호기준: 청소년유해매체물 광고는 성인인증 후에만 보이거나 대체 이미지(19 마크)로 가려짐.
- 취약기준: 미인증 상태에서 성인용 광고·썸네일이 그대로 노출됨.
- 조치방안: 성인 상품·광고는 성인인증(본인확인기관 연령 확인) 완료 세션에만 노출하고, 미인증 시 "19세 이상만 볼 수 있습니다" 대체 이미지를 띄운다. 광고 운영 정책에 유해매체물 광고 게재 기준을 둔다.
- 증적: 미인증 상태 화면 스크린샷(성인 이미지는 흐림 처리)
- 비고: 법령 의무. 연령 확인 방법은 NET-23B-01(주민등록번호 미수집)과 함께 본다.

### NET-42C-01 청소년보호책임자 지정·업무
- 근거: 법 제42조의3(L626-629); 영 제25조~제27조(L632-643); 과태료 법 제76조제4항제3호(L2635)
- 요구사항: 전년도 말 기준 직전 3개월 일평균 이용자 10만명 이상 또는 정보통신서비스 부문 매출액 10억원 이상이면서 청소년유해매체물을 제공·매개하는 자는 임원 또는 관련 부서장 중에서 청소년보호책임자를 매년 4월 말까지 지정해야 한다. 책임자는 보호계획 수립, 접근제한·관리조치, 종사자 교육, 피해상담·고충처리를 한다.
- 적용조건: 영 제25조 요건을 모두 갖춘 정보통신서비스 제공자
- 점검유형: 서면
- 점검위치: 사이트 하단·청소년보호정책 페이지(공개 여부 참고), 서면
- 점검방법: 서면 확인: 청소년보호책임자 지정 문서(직위·지정일), 청소년보호계획, 교육 실시 기록, 피해상담 처리 기록. 브라우저 보조 확인: 청소년보호정책·책임자 연락처가 사이트에 공개되어 있는지.

- 비고: 법령 의무(2026.1.6. 신설). 신고자 개인정보 수집은 PIPA-15·PIPA-16과 관계. 이용자 보호 범위의 경계 항목이므로 점검 범위 포함 여부는 사용자 결정 필요(추출 메모 참고).

### NET-45C-01 정보보호 최고책임자(CISO) 지정·신고·겸직제한

CISO는 정보보호 계획, 정기 감사, 위험 평가, 교육·모의훈련, 인력·예산, 이사회 보고, 서비스 도입·변경 시 보안성 검토, 위탁·클라우드 사업자 정기 보안점검을 총괄한다.

- 점검위치: 서면
- 점검방법: 서면 확인: CISO 지정 문서(직위·임원 여부), 신고 접수증, 자격 증빙, 겸직 현황(겸직금지 대상이면 상근·단독 업무 확인), 연간 업무 수행 기록(이사회 보고, 보안성 검토, 수탁사 점검).
- 양호기준: 적격 임원 지정, 기한 내 신고, 겸직금지 준수, 업무 수행 기록 존재.

- 조치방안: 이사회 또는 대표 결재로 CISO를 지정하고 과기정통부 지정신고서를 제출한다. 겸직금지 대상이면 CISO를 정보보호 전담 상근 임원으로 둔다. CISO 연간 업무계획(감사·위험평가·교육·훈련·이사회 보고·수탁사 점검)을 세우고 실적을 남긴다.
- 증적: 서면 문서
- 비고: 법령 의무. CISO는 개인정보 보호책임자(CPO) 업무를 겸할 수 있음(법 제45조의3제4항제2호라목) — PIPA-31과 관계. 수탁사 점검은 PIPA-26과 관계.

### NET-47-02 인증 표시의 정확성

- 양호기준: 피해구제 절차가 있고 14일 이내 제출.
- 취약기준: 절차 없음, 미제출·지연.
- 조치방안: 침해사고 대응 절차에 피해구제(보상 기준, 민원 창구) 단계와 "신고일+14일 제출" 기한 관리를 넣는다.
- 증적: 서면 문서
- 비고: 법령 의무(2026.3.31. 신설). 이용자 통지 항목(NET-48C-02)에 피해구제 내용이 포함됨.

### NET-49B-01 피싱 등 속이는 행위 발견 시 신고·약관
- 근거: 법 제49조의2제1항·제2항·제5항·제6항(L1888-1899); 영 제60조의17(L1903-1907)
- 요구사항: 누구든지 속이는 행위로 타인의 정보를 수집하거나 제공을 유인해서는 안 되며, 정보통신서비스 제공자는 그런 위반 사실을 발견하면 즉시 과기정통부 또는 KISA에 신고해야 한다. 정부 요청에 따라 접속경로 차단·이용자 통지 등을 하려면 약관에 조치 사유·내용, 중지 기간, 이의제기 절차, 통지 방법을 정해야 한다.
- 적용조건: 모든 정보통신서비스 제공자(약관 사항은 해당 조치를 하는 자)
- 점검유형: 서면
- 점검위치: 서면, 이용약관
- 점검방법: 서면 확인: 자사 사칭 피싱 사이트·문자 발견 시 신고 절차와 이력. 브라우저 보조 확인: 약관에 피해예방 조치 조항이 있는지, 사이트에 "사칭 주의" 안내가 있는지.
- 양호기준: 사칭 탐지·신고 절차와 이력이 있음.
- 취약기준: 발견 후 신고하지 않음, 절차 없음.
- 조치방안: 자사 사칭 도메인·문자 모니터링과 KISA(118, 보호나라) 즉시 신고 절차를 만들고, 공지사항에 사칭 주의 안내를 게시한다.
- 증적: 서면 문서
- 비고: 신고는 법령 의무. 이 조는 점검 주체인 Claude가 로그인 화면 등을 다룰 때도 지켜야 하는 금지 규정이므로 점검 중 이용자 정보 유도 행위를 하지 않는다.

## E. 영리목적 광고성 정보 전송

### NET-50-01 광고성 정보 사전 수신동의(명시적·채널별)
- 근거: 법 제50조제1항(L1929-1931); 영 제61조제1항(L1948); 과태료 법 제76조제2항제7호(L2606)
- 요구사항: 전자적 전송매체(문자, 이메일, 앱 푸시, 메신저 등)로 영리목적 광고성 정보를 보내려면 수신자의 명시적인 사전 동의를 받아야 한다. 예외: 거래관계로 직접 연락처를 받은 자가 거래 종료일부터 6개월 이내에 같은 종류 재화·용역 광고를 보내는 경우, 방문판매법상 전화권유판매자가 수집출처를 육성으로 고지하는 경우.
- 적용조건: 광고성 정보를 전송하는 모든 자
- 점검유형: 관찰
- 점검위치: 회원가입 약관동의 화면, 마이페이지 수신설정, 이벤트·뉴스레터 신청 화면, 앱 푸시 설정
- 점검방법: (1) 회원가입 동의 화면에서 광고성 정보 수신동의가 필수 약관과 분리된 [선택] 항목인지, 기본값이 체크 해제인지 DOM(`input[type=checkbox]`의 `checked` 속성)으로 확인. (2) "전체 동의"에 광고 수신이 포함될 때 개별 해제가 가능한지 확인. (3) 채널(SMS·이메일·푸시)별 동의 선택이 가능한지 확인. (4) 마이페이지 수신설정 화면에서 현재 동의 상태와 채널 구분을 읽기만 함. 제출·저장은 하지 않음.
- 양호기준: 광고 수신동의가 선택 항목으로 분리되고 기본 미체크, 채널별로 선택 가능, 동의하지 않아도 가입 가능.
- 취약기준: 광고 수신이 필수 약관에 포함, 기본 체크, 미동의 시 가입 불가, 이용약관 동의만으로 광고 발송.
- 조치방안: 가입 화면에 "[선택] 광고성 정보 수신 동의 □ 문자 □ 이메일 □ 앱 푸시"를 필수 약관과 분리해 두고 기본값을 해제한다. 동의 문구에 "동의하지 않아도 회원가입·서비스 이용이 가능합니다"를 넣는다. 동의 일시·채널·방법을 DB에 기록해 2년 재확인(NET-50-07)과 처리결과 통지(NET-50-06)에 쓴다.
- 증적: 동의 화면 스크린샷, 체크박스 DOM 속성, 수신설정 화면(개인정보 마스킹 필요)
- 비고: 법령 의무. 마케팅 목적 개인정보 이용 동의(PIPA 제22조)와 광고 수신동의(망법 제50조)는 별개이므로 둘 다 확인 — PIPA-22과 관계, STD-12-01과 관계. 거래관계 예외 적용 여부는 서면 확인 필요.

### NET-50-02 야간(21시~08시) 광고 전송 별도 동의
- 근거: 법 제50조제3항(L1933); 영 제61조제2항(L1949); 과태료 법 제76조제2항제7호
- 요구사항: 오후 9시부터 다음 날 오전 8시 사이에 광고성 정보를 보내려면 일반 수신동의와 별도로 사전 동의를 받아야 한다. 전자우편은 예외.
- 적용조건: 문자·앱 푸시·메신저 등 전자우편 외 매체로 야간 광고를 보내는 자
- 점검유형: 관찰
- 점검위치: 회원가입 동의 화면, 앱 푸시 설정, 마이페이지 수신설정
- 점검방법: (1) 수신동의 화면·설정에 야간 수신동의 항목이 일반 광고 수신동의와 분리되어 있는지 확인. (2) 야간 동의 항목 기본값이 해제인지 DOM 확인. (3) 야간 동의 없이 야간 광고가 오는지는 사용자 수신 이력(문자·푸시 수신 시각 스크린샷)으로 확인.
- 양호기준: 야간 수신동의가 별도 선택 항목으로 있거나, 야간에는 광고를 보내지 않는 정책이 서면으로 확인됨.
- 취약기준: 야간 동의 항목 없이 야간 광고 발송, 일반 동의에 야간 동의를 포함.
- 조치방안: "[선택] 야간(21:00~08:00) 광고성 정보 수신 동의" 항목을 따로 두고 기본 해제한다. 발송 시스템에서 야간 동의자 외에는 21시~08시 광고 발송을 차단하는 스케줄 제한을 건다.
- 증적: 동의 화면 스크린샷, 사용자 제공 수신 이력(전화번호 등 마스킹)
- 비고: 법령 의무. 앱 푸시도 전자적 전송매체에 포함(방송통신위원회 안내서 해석 — 원문 미제공).

### NET-50-03 수신거부·철회 후 전송 금지와 철회 방해 금지
- 근거: 법 제50조제2항, 제5항제1호(L1932, L1938); 과태료 법 제76조제2항제7호
- 요구사항: 수신자가 수신거부 의사를 표시하거나 동의를 철회하면 광고를 보내서는 안 되고, 수신거부·철회를 회피·방해해서는 안 된다.
- 적용조건: 광고성 정보를 전송하는 모든 자
- 점검유형: 능동(승인)
- 점검위치: 마이페이지 수신설정, 광고 메일의 수신거부 링크 랜딩 페이지, 앱 알림 설정
- 점검방법: (1) 관찰: 마이페이지에서 수신설정 변경 메뉴가 쉽게 찾을 수 있는 위치(2단계 이내)에 있는지, 로그인 없이 수신거부 링크로 거부 가능한지, 거부 절차에 불필요한 추가 정보(비밀번호 재입력, 사유 필수 등)를 요구하는지 확인. (2) 능동(승인): 사용자 승인 후 테스트 계정에서 사용자가 직접 수신거부를 저장하고, Claude는 처리 결과 화면과 이후 광고 수신 여부(사용자 보고)를 기록.
- 양호기준: 철회 메뉴가 쉽게 접근 가능하고 즉시 반영, 철회 후 광고 미수신.
- 취약기준: 철회 메뉴 없음·숨김, 고객센터 전화로만 가능, 철회 후에도 광고 수신, 철회 시 과도한 절차.
- 조치방안: 마이페이지 [알림/수신 설정]에 채널별 토글을 두고 저장 즉시 반영한다. 광고 메일·문자의 수신거부 링크는 로그인 없이 원클릭으로 처리되게 한다. 발송 직전 수신동의 상태를 다시 조회하는 로직을 넣는다.
- 증적: 수신설정 메뉴 경로 스크린샷, 철회 처리 화면(사용자 테스트 계정)
- 비고: 법령 의무. 철회 저장은 데이터 변경이므로 테스트 계정·사용자 직접 입력·항목별 승인 원칙 적용.

### NET-50-04 광고성 정보 표시사항((광고)·전송자·수신거부 방법)
- 근거: 법 제50조제4항(L1934-1936); 영 제61조제3항·별표 6(L1950); 과태료 법 제76조제2항제8호(L2607)
- 요구사항: 광고성 정보에 전송자 명칭·연락처와 수신거부·수신동의 철회를 쉽게 할 수 있는 조치·방법을 구체적으로 밝혀야 한다(표시 위치·방법은 영 별표 6).
- 적용조건: 광고성 정보를 전송하는 모든 자
- 점검유형: 관찰
- 점검위치: 사용자가 받은 광고 문자·이메일·앱 푸시 샘플, 웹 이메일 수신함(사용자 계정)
- 점검방법: 사용자에게 최근 광고 문자·이메일·푸시 샘플(스크린샷 또는 사용자가 연 이메일 화면)을 받아 (1) 시작 부분 "(광고)" 표시, (2) 전송자 명칭·연락처, (3) 수신거부 방법(문자: 무료 수신거부 전화번호, 이메일: 수신거부 링크) 표시를 확인한다. "(광고)" 표기를 "(광/고)", "(광 고)" 등으로 변칙 표기했는지 확인.
- 양호기준: 3개 요소가 모두 있고 "(광고)"가 정확히 표기됨.
- 취약기준: "(광고)" 누락·변칙 표기, 전송자·연락처 누락, 수신거부 방법 누락.
- 조치방안: 문자는 "(광고)[회사명] 본문… 무료거부 080-XXX-XXXX", 이메일은 제목 맨 앞 "(광고)"와 본문 하단에 전송자 명칭·주소·전화번호·수신거부 링크, 앱 푸시는 "(광고)" 표시와 앱 내 수신거부 경로 안내를 넣는다. 발송 템플릿에 고정 문구를 넣어 누락을 막는다.
- 증적: 광고 샘플 스크린샷(수신자 번호·이메일 마스킹 필요)
- 비고: 법령 의무. 영 별표 6 원문은 소스 파일에 수록되지 않음 — 위 표시 위치(문자 시작 "(광고)", 이메일 제목 앞 "(광고)", 080 무료거부)는 일반적으로 알려진 별표 6 및 방송통신위원회 안내서 내용이므로 현행 별표 원문 대조 필요. 브라우저로 직접 수신 확인이 어려워 사용자 제공 샘플에 의존.

### NET-50-05 수신거부·철회 비용 무료 제공
- 근거: 법 제50조제6항(L1943); 영 제62조·별표 6(L1951); 과태료 법 제76조제2항제9호(L2608)
- 요구사항: 수신자가 수신거부·동의 철회를 할 때 전화요금 등 비용을 부담하지 않도록 무료전화서비스 등을 광고에 명시해 제공해야 한다.
- 적용조건: 광고성 정보를 전송하는 모든 자
- 점검유형: 관찰
- 점검위치: 광고 샘플, 수신거부 링크 랜딩 페이지
- 점검방법: 광고 샘플의 수신거부 수단이 080 무료전화·무료 회신·수신거부 링크 등 무료인지 확인한다. 유료 전화번호(일반 대표번호, 1588 등)만 있으면 취약.
- 양호기준: 무료 수신거부 수단이 명시됨.
- 취약기준: 유료 전화로만 거부 가능, 거부 시 데이터 요금이 드는 유료 앱 접속만 안내.
- 조치방안: 080 수신거부 번호를 개통해 문자 하단에 "무료거부 080-XXX-XXXX"로 적고, 이메일·푸시는 로그인 없는 수신거부 링크·앱 설정 경로를 제공한다.
- 증적: 광고 샘플 스크린샷(마스킹)
- 비고: 법령 의무. 별표 6 원문 미수록(NET-50-04 비고와 같음).

### NET-50-06 수신동의·거부·철회 처리결과 14일 내 통지
- 근거: 법 제50조제7항(L1944); 영 제62조의2(L1952-1955); 과태료 법 제76조제4항제12호의3(L2654)
- 요구사항: 수신자가 수신동의·거부·철회 의사를 표시하면 그 날부터 14일 이내에 전송자 명칭, 동의·거부·철회 사실과 의사표시 날짜, 처리 결과를 알려야 한다.
- 적용조건: 광고성 정보를 전송하려는 모든 자
- 점검유형: 능동(승인)
- 점검위치: 마이페이지 수신설정 저장 직후 화면, 사용자 이메일·문자

### NET-50-08 광고 전송 금지행위(자동생성·출처은닉·기망)

- 조치방안: 발송 시스템이 수신동의 DB 외 연락처를 쓰지 못하게 제한하고, 발신번호 사전등록·이메일 SPF/DKIM 설정으로 발신 출처를 명확히 한다.
- 증적: 서면 문서
- 비고: 법령 의무(과징금 대상, 법 제50조의9).

### NET-50C-01 광고 전송 위탁 시 자격 확인·관리감독

- 요구사항: 문자 대량발송(전기통신사업법 제2조제14호나목 역무) 광고 전송을 위탁하려면 전송자격인증을 받은 자에게 위탁해야 하고, 위탁자는 수탁자가 제50조를 위반하지 않도록 관리·감독해야 한다. 수탁자는 손해배상 책임에서 위탁자 직원으로 본다.
- 적용조건: 광고 문자·메시지 발송을 외부 업체에 위탁하는 자
- 점검유형: 서면
- 점검위치: 서면
- 점검방법: 서면 확인: 발송 대행 계약서, 수탁자 전송자격인증 증빙, 위탁자의 관리·감독 기록(발송 내역 점검).
- 양호기준: 인증받은 수탁자, 계약상 법 준수 의무와 점검 기록.

- 조치방안: 발송 대행사 선정 시 전송자격인증서를 받고, 계약서에 수신동의·야간·표시의무 준수 조항을 넣으며 분기별 발송 내역을 점검한다.
- 증적: 서면 문서
- 비고: 법령 의무(제1항은 2026.3.31. 신설). 개인정보 처리 위탁(PIPA 제26조)과 함께 관리 — PIPA-26과 관계.

### NET-50D-01 전송 역무 제공 거부 시 계약 명시·통지
- 근거: 법 제50조의4(L1978-1989); 영 제62조의4(L1992); 과태료 법 제76조제2항제9호의4(L2611)
- 요구사항: 메시지·메일 전송 역무를 제공하는 정보통신서비스 제공자가 광고로 인한 장애·수신 거부를 이유로 역무를 거부하려면 이용계약에 그 사항을 포함하고 이해관계인에게 알려야 하며, 자기 서비스가 불법 광고 전송에 이용되면 즉시 중단·계약 해지·취약점 개선 등 조치를 해야 한다.
- 적용조건: 문자·메일 발송 서비스 등 전송 역무 제공자
- 점검유형: 서면
- 점검위치: 이용약관, 서면
- 점검방법: 이용약관에 역무 제공 거부 사유가 있는지 확인. 서면 확인: 불법 광고 이용 시 조치 기준(별표 6의2)과 조치 이력.
- 양호기준: 약관에 거부 사유 명시, 위반 이용 시 조치 기록.
- 취약기준: 약관 근거 없이 거부, 불법 광고 이용 방치.
- 조치방안: 이용약관에 "스팸 전송 시 서비스 제한" 조항을 두고, 위반 탐지 시 즉시 발송 중단·고객 통지·재발방지 계획 절차를 운영한다.
- 증적: 약관 조항 스크린샷
- 비고: 법령 의무. 일반 웹서비스는 해당없음(메시징 플랫폼 등만).

### NET-50E-01 광고·개인정보 수집 프로그램 설치 시 동의·용도·삭제방법 고지
- 근거: 법 제50조의5(L1995); 영 제63조(L1997); 과태료 법 제76조제2항제10호(L2612)
- 요구사항: 광고가 보이게 하거나 개인정보를 수집하는 프로그램을 이용자 컴퓨터·휴대전화 등에 설치하려면 이용자 동의를 받고 프로그램의 용도와 삭제방법을 알려야 한다.
- 적용조건: 사이트 이용 과정에서 설치형 프로그램(실행파일, 브라우저 확장, 툴바, 앱, 보안·인증 모듈)을 설치하게 하는 자
- 점검유형: 관찰
- 점검위치: 로그인·결제·본인확인 등 설치 유도 화면, 다운로드 안내 페이지
- 점검방법: 설치 유도 화면이 있으면 설치 전에 용도와 삭제방법 안내, 동의 절차가 있는지 페이지 텍스트로 확인한다(설치·다운로드는 하지 않음). 자동 다운로드가 시작되는지는 네트워크 요청 목록에서 확인.
- 양호기준: 설치 전 동의, 용도·삭제방법 안내가 있음.
- 취약기준: 안내·동의 없이 설치 유도 또는 자동 다운로드, 광고 모듈 끼워 설치.
- 조치방안: 설치 안내 화면에 "이 프로그램은 ○○ 용도로 사용되며, [제어판 > 프로그램 제거]에서 삭제할 수 있습니다. 설치에 동의하십니까?"를 표시하고 동의 버튼 후 다운로드를 시작한다. 광고·수집 모듈 동봉을 금지한다.
- 증적: 설치 안내 화면 스크린샷, 네트워크 요청 목록
- 비고: 법령 의무. 웹페이지에 삽입된 스크립트·쿠키(트래커)는 "설치"로 보기 어려워 이 조 대상인지 해석이 갈림 — 트래커·쿠키는 PIPA 처리방침 항목(STD-19-01 제6호)으로 점검하고 이 항목은 설치형 프로그램에 한정할지 사용자 결정 필요.

### 원문 간 불일치·확인 필요
- 영 별표 6(광고 표시 방법·무료 수신거부)이 소스에 없음. NET-50-04·NET-50-05의 표시 위치·형식은 일반적으로 알려진 내용으로 적었으므로 현행 별표 원문 대조 필요.
- 청소년유해매체물 전자적 표시 형식은 방송미디어통신위원회 고시 위임(원문 미제공). NET-42-01의 전자적 표시 판정은 고시 확인 전까지 "확인 필요"로 둘 것을 권장.
- 소스는 2026.9.29. 개정 법률 기준이며 감독기관 명칭이 "방송미디어통신위원회"로 바뀌어 있음. 기존 안내서(방송통신위원회 명의)와 명칭이 다를 수 있음.
- 침해사고 신고(망법 24시간, 과기정통부·KISA)와 개인정보 유출 신고(PIPA 72시간, 보호위원회·KISA)는 기한과 신고처가 다름. 망법 제48조의3제1항 후단은 "다른 법률에 따른 신고를 했으면 신고한 것으로 본다"고 하나, PIPA 72시간 신고로 망법 24시간 기한이 충족되는지는 조문상 불명확 → 보고서에서는 두 기한을 모두 안내하는 것을 권장.
- 제48조의3제4항 침해사고 이용자 통지와 영 제58조의9는 2026.9.30. 시행된 신설 조항으로, 기존 안내서에는 없음.
- 영 제36조의7 등에서 개정 연혁 표기가 "2026. 9. 30."으로 법률(2026. 9. 29.)과 하루 차이가 있으나 원문 그대로 적음.
