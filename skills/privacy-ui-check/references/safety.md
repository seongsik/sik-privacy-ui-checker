# 안전 규칙 — 운영 데이터를 바꾸지 않는다

설계서 7장의 장치와, 점검자가 지킬 행동 규칙이다. 스크립트가 막지 못하는 부분은 사람(Claude)의 행동 규칙으로 지킨다.

## 스크립트가 막는 것(scripts/guard.py, session.py, collect.py, active_test.py)

| 장치 | 내용 |
|---|---|
| 쓰기 메서드 차단 | GET·HEAD·OPTIONS 외 요청(form 제출, fetch POST/PUT/PATCH/DELETE, sendBeacon)은 네트워크 단계에서 막는다 |
| WebSocket | 서버에 연결하지 않고, 페이지가 보내려던 메시지만 기록한다 |
| Service Worker | 점검 컨텍스트에서 등록을 막는다(그 요청은 route 로 가로챌 수 없어서). `install_guard` 는 막힌 컨텍스트에서만 동작한다 |
| 상태 변경 GET | 기본 패턴(logout·signout, /delete·/remove·/destroy·/del, `action=delete` 같은 파라미터; 대소문자·퍼센트 인코딩·`;jsessionid`·.do/.jsp 확장자 정규화)과 menu_map 의 `deny_patterns` 를 막는다. 도메인 밖 GET(SSO 로그아웃 등)에도 적용한다 |
| 범위 | intake.allowed_domains 밖으로의 화면 이동(iframe 포함)은 막는다. 외부 리소스 GET 은 허용한다 |
| 조회성 POST | 사용자가 확인한 정규식(`--allow-post`)만 통과한다 |
| 능동 시험 | 승인 대상(메서드 + URL, 쿼리 제외)만 최대 횟수까지 직접 보내고, 그 응답의 리다이렉트는 따라가지 않는다. 대상이 범위 밖이거나 금지 목록에 걸리면 시험을 거부한다 |
| 원본 격리 | 세션 파일·원본 폴더가 작업 폴더 안이면 거부한다. HAR 의 비밀번호·토큰·세션·API 키 값과 쿠키·인증 헤더 값, cookies.json 의 값은 `***` 로 저장한다 |
| 가림 실패 시 닫힘 | 가림 좌표가 없거나 흔들렸거나 잘못되면 배포용 이미지를 만들지 않는다 |

## 사람이 지키는 것

- 로그인 전에는 쓰기 차단이 꺼져 있다. 로그인 직후 도착 화면에서 바로 수집을 시작하지 않는다(1단계 안내).
- 막힌 요청 때문에 화면이 깨져도 **허용 목록을 스스로 넓히지 않는다.** 막힌 요청 목록(meta.json `blocked`)을 사용자에게 보여 주고 조회용인지 확인받는다.
- 메뉴맵에서 상태를 바꿀 것 같은 링크(로그아웃, 삭제, 취소, 승인, 발송, 탈퇴 실행, 결제)를 찾으면 `blocked` 로 두고 사용자에게 알린다.
- 다른 정보주체의 개인정보를 조회하게 되는 시도(주소의 회원번호·주문번호 바꾸기 등)를 하지 않는다.
- 검색엔진 검색처럼 대상 사이트 밖 서비스에 대상 정보를 보내는 확인은 사용자 동의 후에만 한다.
- 원본 폴더의 파일(특히 dom.html, storage.json)에는 가리지 않은 개인정보가 있다. 채팅에 그 값을 옮겨 적지 않는다.

## 즉시 멈추는 조건

| 상황 | 수집기 신호 | 할 일 |
|---|---|---|
| 429 Too Many Requests | `rate-limited` | 멈춤. 사용자에게 알리고 간격·시간대를 정한다 |
| WAF 차단 화면 | `waf` | 멈춤. 점검 IP 허용(화이트리스트) 여부를 사용자에게 묻는다 |
| CAPTCHA | `captcha` | 멈춤. 풀지 않는다 |
| 403 연속 2회 | `forbidden-repeated` | 멈춤. 권한·차단 여부를 사용자에게 확인 |
| 로그인 화면으로 돌아감 | `session-expired` | 사용자가 다시 로그인하고 같은 명령으로 이어 간다 |

사이트 부담: 탭 하나, 순차 수집, 화면 사이 기본 1.5초 대기(collect.py `delay_s`).
